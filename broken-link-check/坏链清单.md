# KOMOJU 文档坏链清单（通俗版 · 精确定位）

> 对 KOMOJU 全套 164 篇英文文档的**内部跳转链接**做离线坏链扫描，共发现 **31 条**坏链（`MISSING_TARGET` 20 · `LEGACY_HOST` 6 · `BROKEN_ANCHOR` 2 · `README_PAGE_ORPHAN` 2 · `LEGACY_SLUG` 1）。
> 每条给出两种定位：**① `.md` 原文位置**（点开是纯文本 `.md` 文件，可 Ctrl+F；下方直接摘录出错片段）；**② 渲染页**（不带 `.md` 的正式文档页，点开对照阅读）。
>
> 判定与《问题清单》互补、**不重复**：那份聚焦「拼写错、抄错、示例对不上、坏 JSON、前后矛盾」这类**内容缺陷**；本清单只查**跳转链接能不能点到目标**——即点进去 404、锚点跳空、指向旧域名或 ReadMe 遗留构造。扫描器与坏链定义见 `scripts/check_links.py`（离线可复现，退出码 `0` 无坏链 / `1` 有坏链 / `2` 用法错）。

## 一、komoju_docs 的内部跳转链接模式（判定依据）

站点 host = `doc.komoju.com`；本地快照分 `docs / reference / recipes / changelog` 四目录。摸清语料后，内部跳转共有 **6 种写法**，扫描器据此归一化再判定：

| 写法 | 示例 | 说明 |
|---|---|---|
| 完整 URL | `https://doc.komoju.com/docs/webhooks#secret-token` | 站内链接写成绝对 URL，**不带 `.md`**（与 `llms.txt` 索引带 `.md` 不同） |
| 根相对 | `/reference/sessions`、`/docs/tokens`、`/reference`（区首页） | 省略 host，最常见 |
| 裸相对 | `getting-started-with-woocommerce` | 无 scheme 无前导斜杠，按同目录（`docs/`）解析 |
| 版本前缀 | `https://doc.komoju.com/v2025-01-28/docs/...`、`/v1.0/recipes/...` | 需剥掉 `vYYYY-MM-DD` / `v1.0` 版本段再解析 |
| 组件属性 | `<TutorialTile link="https://doc.komoju.com/v1.0/recipes/<slug>" />` | recipes 只通过组件 `link=` / `src=` 引用，markdown `[]()` 里没有 |
| 页内锚点 | `#secret-token`、`...docs/authentication#api-version` | 指向本页或目标页标题锚点 |

**目录/清单**：`llms.txt` 是站点权威机读索引（167 条，全带 `.md`），与本地文件共同构成 slug manifest。**非跳转资产**：`files.readme.io`（图片 CDN）、`help / en / ja / about.komoju` 及第三方域名归为外链，离线不判死（加 `--live` 才联网探活）。

## 二、为 KOMOJU 定义的坏链类型

沿用 volc-bp-doc-fetch `check-links` 的流水线思想（extract → 分类 `link_type` → 对照 manifest 解析 → 给 verdict），但类型与判据按 KOMOJU 实况重写：

| 坏链类型 | 判定 | 后果 |
|---|---|---|
| `MISSING_TARGET` | 内部 doc/reference/recipe slug 本地与 `llms.txt` 均无 | 点进去 404 |
| `BROKEN_ANCHOR` | 目标页存在，但 `#anchor` 匹配不到任何标题 | 跳到页顶 / 跳空 |
| `README_PAGE_ORPHAN` | `/page/<slug>` 这类 ReadMe 专有构造，无对应文档 | 死链 |
| `LEGACY_SLUG` | 单段根级遗留 slug（如 `/payments-1`）映射不到任何页 | 死链 |
| `LEGACY_HOST` | 指向旧域名 `komoju-docs.readme.io` 而非 `doc.komoju.com` | 跳出当前站 / 潜在失效 |

## 四、成因归纳与修复方向

- **ReadMe → 现行站点迁移遗留（最大宗，占 26 处）**：`-1` / `-2` 自增后缀（`sessions-1`、`platform-model-1`、`payments-2`）、动词式 slug（`get_payments-id`、`post_payments`、`post_customers`）、`/page/` 构造、`/payments-1` 根级 slug、`komoju-docs.readme.io` 旧域名——全是从 ReadMe 平台迁出时未做 slug 归一化。修复方向：批量映射回现行 `reference/<name>` slug 与 `doc.komoju.com` 域名。
- **拼写/锚点笔误（3 处）**：`creatession`、`#testing-your-integration-1`、`#life_cycle`。
- **草稿路径泄漏（1 处）**：`../finished_drafts/...` 本地相对路径被发布，应替换为正式 `/docs/getting-started-with-shopify`。
- **`docs/tokens` 概念错指（2 处）**：Tokens 页实际在 `reference/`，误写成 `docs/`。

> 复核或增量重跑：`python3 scripts/check_links.py`（人读）或 `--json`（结构化）；本清单基于 `scripts/fetch_komoju_docs.py` 抓取的快照产出，需最新数据时可一键重抓再扫。
