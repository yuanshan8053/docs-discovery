项目历程 / JOURNEY

先摸清语料，再定义坏链，各个击破

起点是对文档一无所知。节奏是「抓快照 → 摸清跳转写法 → 三条线分别质检 → 门禁收口交付」。

01

抓取全站快照

基于官网 llms.txt 机读清单（167 条）拉取最新文档，按 docs/reference/recipes/changelog 分目录落盘。三份分析全部基于同一快照，需要更新时 fetch_komoju_docs.py 一键重抓。

02

摸清内部跳转写法

先啃语料：内部跳转共 6 种写法——完整 URL、根相对、裸相对、版本前缀 /v1.0/、组件属性 link=、页内锚点。扫描器据此归一化，再谈判死，避免误伤。

03

三条线分别质检

AI 友好度查内容错（拼写/枚举/示例/矛盾），增强建议补内容缺（字段说明/错误码/限流），坏链扫描查链接死（404/锚点跳空/旧域名）。三者互补、严格去重。

04

门禁收口交付

所有 .md 交付物提交前必须过中文书写规范门（半角标点残留检查）。首份交付曾查出 118 处残留，此后确立硬纪律：门禁不过，不予交付。

质量纪律 / DISCIPLINE

怎么守住交付质量

标准落到每一条可机检的纪律上。

discipline/precise-location.rule 每条双定位

01　精确定位，不放空话

每条问题都给两种定位：.md 原文行号 + 摘录、及渲染页链接。渲染页字段 JS 动态生成、常搜不到，故精确定位一律以 .md 行号为准。

discipline/no-overlap.rule 三线互补

02　三份成果严格去重

质检查内容错、增强补内容缺、坏链查链接死——同一问题只在一份里出现。增强清单开篇即声明：质检已提的一律不再收录。

discipline/offline-reproducible.rule exit code = CI

03　离线可复现，退出码定判

坏链判定不依赖联网：比对本地文件 + llms.txt 清单；外链默认只分类不判死，--live 才探活。退出码 0/1/2 直接当 CI 判据。

discipline/zh-punct-gate.rule 门禁不过不交付

04　中文书写规范门，一处不漏

中文正文半角标点紧邻汉字即判残留，必须转全角（代码块/行内代码/URL 自动豁免）。首份交付曾查出 118 处残留，此后：门禁不过，不予交付。
